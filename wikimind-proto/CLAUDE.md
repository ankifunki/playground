# Wikimind prototypes

Front-end-only React prototypes for **Wikimind**: a read-only surface that exposes the knowledge inside Asoka to customers. **Asoka is not one agent:** it is a team of specialist sysadmin agents, each with one job (Approvals, Access, Security, Finance ops, Integrations, Support). Everything is faked in the browser. No backend. Vite + React + TypeScript, run locally.

Brief: https://docs.google.com/document/d/1hVtsbMiSN-4_3rn8jfR_p6HhGTC3foUkvRIHkwXpc3c (not readable from Claude Code; Ankit shared it as screenshots). The essentials:

- **What it is:** a read-only surface that exposes Asoka's brain to customers, a living "internal Wikipedia". Knowledge is auto-generated by Asoka and continually verified by its expert sysadmins. Not the day-to-day interface (that's Slack, Teams, tickets): Wikimind is the **proof layer**, the demo that wins and retains buyers, the reference for IT power users, and the **citation source when Asoka justifies its actions**.
- **How knowledge works:** observations (Slack, tickets, requests, the Salesforce changelog and config mutations, meetings) update blocks autonomously, each linked to the observation and reflection that caused it. A flat corpus of linked Markdown pages, no folders. Provenance like git blame for every block. Asoka notices its own gaps and interviews people. A human sysadmin's verification is the highest trust tier and can be revoked when new observations contradict it.
- **Problem:** docs (even for Salesforce) are incomplete, stale, abandoned, and miss tribal knowledge. Existing tools aren't trustworthy (complete vs incomplete, current vs stale) and aren't AI-native (walls of text, chatbot bolted on).
- **Goals:** trust ("Asoka is a trust company"), alive and living (a window into something thinking right now), AI-native (AI is the author of content, diagrams and media, and the primary way to interact), beautiful (diagrams, flowcharts, animations, screen recordings of how actions work).
- **Audiences:** (1) CIO / Head of Enterprise Apps in a live demo, who should leave believing it was assembled automatically (and could be for their org), is more exhaustive, current and *provably* accurate, is continuously curated by AI with a human expert, and refines itself by interviewing people; (2) architects and developers, the true users: how is it configured, what automations touch this object, what policies govern this process; (3) business users landing from a citation, e.g. when Asoka pushes back on a Slack request because it violates a policy and cites the page.
- **Specs:** 6.1 Page, a long-form structured page with headings, linked to related pages, where evidence (observations, reasoning, edits, verification) is highly visible and tightly connected to the content. 6.2 Home, between Wikipedia's home page and the New York Times front page: what Asoka recently observed, learned and changed across the Salesforce environment and processes; an immediate sense of a living system; ambitious ways to make the scale and aliveness of what it understands obvious.

## Layout

```
src/App.tsx                 variant switcher (?v=b..h), loads one variant at a time
src/useVariantCss.ts        mounts a variant's stylesheet only while it is on screen
src/fonts.css               Figtree, DM Mono (@fontsource) and Geist Serif (geist package), bundled locally
src/variants/<name>/        one folder per variant: index.tsx, a store (state + actions), components, data.ts, styles.css
```

Each variant's CSS is the original stylesheet, loaded with `?inline` and injected while the variant is mounted, so generic class names in different variants never collide.

## Running it

```
npm install
npm run dev        # http://localhost:5173/?v=h  (h = Wikimind 5, the default)
npm run build      # type-check and production build into dist/
```

Light mode by default, whatever the OS prefers. The sun/moon button at the right of the variant bar switches to dark and remembers it (`localStorage` `wikimind-theme`); `index.html` sets `data-theme` before first paint, and every variant styles both themes through `:root[data-theme]`.

Hosted for preview on Vercel (project `wikimind-proto`, root directory `wikimind-proto`, Vite build) behind a password page: `middleware.js` reads `WIKIMIND_PASSWORD` from the Vercel env (never commit it). The project is not Git-connected, so deploy explicitly after pushing.

## Demo controls (Wikimind 3, 4 and 5)

- `L`: Maria answers the flat-renewals question. The Approvals agent rewrites the card (old sentence struck, new one written in). Also reachable via "Simulate her reply" in Questions. There is no automatic timer.
- `A`: the person an agent is asking answers the visitor's newest open question immediately. Otherwise they answer 15 seconds after the visitor taps "Ask".
- Wikimind 4 only: `S` (or the Demo link at the bottom of Home, or `#approvals-slack`) opens the page as a visitor arriving from a Slack citation. Maria also answers on her own about 20 seconds after the page opens.
- Wikimind 5: `T` starts the guided tour (also the button on Home), `C` makes the live Salesforce change happen (Finance review moves from over 20% to over 25%; the page rewrites, Dana's verification is withdrawn and restored about 7 seconds later), `E` toggles the evidence lens, `S` arrives from Slack, `H` hands proven work over (Dev approves after about 2 seconds). On the page, a receipt arrives after about 12 seconds, the Salesforce change at about 26, and Maria's answer at about 52.
- `/` focuses the ask box. Esc closes the source sheet, then the conversation.
- Unknown questions offer "Ask <name>" or "Not now". Undo is available for 5 seconds after asking. No agent contacts anyone without the visitor's tap.

## Design goals (from the brief)

Trust, alive and living, AI-native, beautiful. Two specs: **Page** (trust is the central challenge: evidence tied to each block, git-blame style provenance) and **Home** (front page that makes Asoka's scale and aliveness obvious).

Audiences in priority order: CIO buyer in a demo, architects and developers (real users), business users arriving from Asoka's citations in Slack.

## Decisions already made (don't relitigate without asking)

- **Never use neumorphism / soft-UI.** Not for anything, not even the map.
- **Nothing should look or read like a wiki.** No gray bordered boxes, blue bracketed citations, infoboxes, underlined tabs, or wiki vocabulary (Talk, History, References, See also, Did you know, Featured article). Borrowed *ideas* are fine if restyled.
- House visual language: warm stone background `#F8F6F2` with warm neutrals, white cards with soft shadows (no hairline borders) **reserved for key content**, indigo accent `#4B45D6`, Geist for UI and body, Geist Mono for tags, labels and counts, Geist Serif for headlines and long reading text. Full dark mode via CSS variables.
- Trust by exception: solid facts carry no mark. Only uncertain, changed, unofficial, or stale content gets marked.
- Ask is persistent at the bottom (composer with attachments, voice, scope toggle), not a header search.
- Unknown questions get "No agent knows that yet, and none will guess," then become open questions that the relevant agent asks a person.
- **Trust is shown as four questions, never "% checked".** In a system that keeps learning, a checked-percentage falls as it learns, and its 100% would mean people reviewing everything (the wiki model). Use: *Is it complete?* (what exists in Salesforce is finite and can reach 100%; unwritten practice is counted, not given a percentage), *Is it right?* (accuracy by spot check, with every miss shown), *Is it current?* (re-read within a day; what's out of date), *What doesn't it know?* (open questions being asked). Per-sentence "checked by a person" stays as a trust tier.
- **Home anchors on the CIO's goal, not on volume.** The headline metric is the share of admin work the agents are trusted to run on their own, with the four questions as the levers that move it. The bar aims for 100%: the hardest work (discounts over 20%, payments, device wipes, admin rights) is still done by people while the agents shadow it and build a track record, and moves to proven when they earn it. Never show a ceiling or a policy cap. Question cards are question, status, action, nothing else; the bar's hover labels carry the detail. Page counts are a footnote proving it was assembled automatically, never the anchor. Widening what agents do alone always goes through a second approver (Dev). Data marks stay in one ink at a few strengths (as few states as possible; grey for not yet). Every look means exactly one status and is named on screen (headline, inline link, or a bracket label), not only on hover; no colour-keyed legends and no dotted patterns. Stat cards: only the stat is serif, everything else is body text.
- **Wikimind 5 type: eight roles, nothing in between.** Display serif 56 (hero stat, page title; 44 on phones), Headline serif 32 (lead story, section headings, every stat; 28 on phones), Title serif 20 (nameplate, item headlines, lede, answers, drawer headlines), Body sans 16, UI sans 14 (400/500), Meta sans 13, Label mono 11/450, Code mono 13 (Salesforce identifiers only). Serif is always 400. Prices and counts outside a stat are sans with tabular figures. The tests fail if any other size appears on Home or the page.
- **Wikimind 5 marks: the 2px bar is the one mark.** Data is drawn in one ink at a few strengths (trust bar, practice frequency, threshold diagram, simulator); colour carries meaning, never data. Status is one label: mono 11 in its tone (green checked by a person, amber unconfirmed or failing, ink2 neutral), led by the same 2px bar, with no fill or outline. Defaults like "Healthy" are never marked. Live is the bar breathing; nothing uses dots. The ring that separates overlapping source tiles matches the surface underneath (`--ring`).
- **Wikimind 5 status: one purpose, one place.** On the page, a status flags a sentence that isn't solid and opens its evidence, so it lives only in the margin beside that sentence (inline after it on narrow screens), always a clickable margin mark, one solid 2px bar, tone colour for meaning. No status labels inline in rows or blocks. On Home, headlines and meta lines say the state in words; the only status text is the lead byline's "Verified by Dana Ruiz".
- **Active vs passive is obvious.** Interactive inputs sit together in one soft-filled panel; everything else in a demo is read-only answer. Cut anything a demo doesn't need to make its point (Try a deal lost its playback controls, toggles, deal types and record mock).
- **The page is a document first (Spec 6.1).** Long-form, headings and subsections, linked to related pages inline; no folder paths (the corpus is flat: "All pages"). Status is one compact strip under the byline, never a dashboard block before the knowledge. Evidence is visible without asking: each section opens with its evidence line, sentences carry margin marks for exceptions, and the Markdown view shows the file with footnotes.
- **Side panels have structure:** header (kicker, the stat repeated, one plain sentence), sections with headers ("What would be handed over · 3 jobs"), and the action pinned to the bottom in a footer with its condition ("Dev approves before any agent does more on its own").
- **Bars are real units with real width:** 3px upright bars about 5.5px apart (Wikimind 4's density), each a round number of completed requests chosen to fill the width (15 on desktop, 10 on the page strip, 50 on phones), and the caption states it. States differ by fill, never by shape or thickness: solid ink, mid grey (ink 45%) bars with exactly two diagonal cuts, 3px tall, at a third and two thirds of the height, so top and bottom are always solid blocks (incomplete: proven, needs your OK). Drawn as one path per bar, not a pattern, plain light grey. Drawn as SVG on whole device pixels.
- **Ask bar:** lines up with the text column on the page; shrinks to a small "Ask anything" pill while reading, grows back to the full composer on click or `/`. The pill is the same input, so focus never breaks.
- **Wikimind 5 layout:** cards only for key content (Home: the trust anchor and the lead story; page: the deal simulator, the Slack arrival and written-in answers). Passive content (the live wire, Changed / Learned / Asking, the trust line, In practice, How it's configured, receipts) sits on the surface between 1px hairlines. Home uses one 3-column grid for every row (the lead story spans two columns, so the live wire lines up with Asking). Radii: cards 12, inner panels 8, floating surfaces 16, pills 999. Details (proofs, previews, provenance) open in a right-side drawer at 900px and wider; phones keep the bottom sheet.
- **Asoka is a team of specialist agents, not one entity.** Never write "Asoka is…" or "Asoka learned…" as if it were a single actor. Every fact, change, question and answer is credited to the agent that did it (`agents.tsx`: square indigo tile + name; sources stay round and neutral). Home shows each agent's reliability, share running on its own, and what is holding it back.

## Craft rules

- **Wikimind 3 and 4 design system** (stay on it): type 11 / 12 / 13 / 14 / 15 / 16 / 18 / 21 / 24 / 28 / 38px plus the clamped display headline; **two weights only: 400 for reading, 500 for emphasis and titles, never 600/700** (`<b>` is 500; Geist Serif stays 400 because it has one real cut and anything heavier is synthesized); radii 8 (small controls), 14 (inner panels), 20 (cards), 24 (floating surfaces: chat, composer, sheets), pills 999; spacing in 4px steps. Both are now airier: 24px card padding (20px on phones), 48px between Home's main sections, 64px above page section headings. Both show sources as an icon pile (one Lucide icon per source kind, green dot when verified) rather than names, and keeps UI copy to what a person needs to act: no explanatory sublines. Tags, pills, labels and kickers are Geist Mono 11px at weight 450, quiet and secondary. Line work: 1px `--hl` hairlines for structure, 2px square bars for data, 1.5px trends. Headlines `text-wrap: balance`, body `text-wrap: pretty`.
- Motion: custom ease-out `cubic-bezier(.23,1,.32,1)`, press feedback `scale(.97)`, hover only inside `@media (hover:hover) and (pointer:fine)`, `-webkit-tap-highlight-color: transparent`, reduced-motion keeps fades but drops movement (Emil Kowalski's design-engineering skill rules).
- Entrances animate only on view change; reveals animate only the element just opened (see the `S.entering` / `S.flash` pattern in wikimind.html).
- Watch for **CSS class collisions**. Real bugs came from reusing generic class names (`.x`, `.cite`, `.ck`, `.obs`) and from element selectors: the shared `header{position:sticky}` rule made Wikimind 5's masthead stick until it became a `div`. Prefer component-specific names, and don't use `<header>` for page content.
- Verify layout at 390px and 1100px+ before calling something done. Playwright screenshots worked well for this.

## Known gaps

- Only "Opportunity approvals" has full content in Wikimind 3. Other links open preview cards.
- Answers are local keyword matches. Live Claude answers (`window.claude.use('sample')`) only work when published as a claude.ai artifact, and fall back gracefully elsewhere.
- Attachments are not actually read. Answers are canned per file type.
- Voice uses the browser's SpeechRecognition API (Chrome, Safari).
